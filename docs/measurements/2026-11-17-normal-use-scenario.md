# 정상 사용 시나리오 실측과 규칙 R6·R7 (2026-11-16~17)

갤럭시 실기기에서 정상 사용만 하며 제품 앱 판정기(`core/usage` Detector)의 오탐을 쟀다. 사용자 설치 앱에서 오탐이 나와 규칙 R6·R7을 추가했다.

## 1. 환경

| 항목 | 값 |
|---|---|
| 기기 | Galaxy S10+ (SM-G975N), Android 12, 시험용(평소 쓰지 않음), 유심 없음 |
| 앱 | 폰주치의 debug (main `342f15f` 판정기 → 이 변경 판정기로 교체 설치) |
| 사용 앱 | 기본 탑재(유튜브·크롬·Gmail·메시지·갤러리·Play 스토어), 직접 설치(네이버, 쿠팡, 네이버 웹툰) |
| 조작 | adb로 화면 좌표를 눌러 진행. 사용 기록에는 터치가 남지 않고(`USER_INTERACTION` 5일간 11건) 화면 전환만 남아, 사람이 누른 것과 기록이 같음 |
| 원자료 | `ml/data/poc/product_obs/scenario_auto_2026-11-12/`, `scenario_auto_2026-11-17/` (레포 제외). 단계별 시각·검사 결과 `steps.csv`, ms 단위 사용 기록 `s10.events.csv`(usageprobe `DumpReceiver`), 설치 앱 `s10.launchers.csv`·`s10.exported.csv` |

## 2. 기존 규칙(R1~R5)의 오탐

정상 사용 단계마다 검사를 돌려 광고로 센 전환을 셌다.

| 앱 종류 | 단계 | 광고로 셈 |
|---|---|---|
| 기본 탑재 앱만 | 유튜브 재생·작은 창·최근 앱, 크롬 검색 → 유튜브·스토어 앱, 공유 → 메시지, 메일 알림 진입, 메일 링크 → 크롬·유튜브, 화면 끄고 켜기 (16구간) | 0 |
| 직접 설치한 네이버 | 첫 실행 권한 창 뒤 복귀, 공유 → 메시지 뒤 복귀, 아이콘·최근 앱으로 다시 열기, 유튜브 링크 뒤 복귀 (약 7분) | 6 → 확인 요청 알림 발생 |

- 기본 탑재 앱은 R1(시스템 앱 제외)이 걸러서 0이었다. [UsageStats 실증](2026-10-26-usagestats-poc.md) §3-2에서 "R1이 오탐을 가린 셈"이라고 적은 한계가 실기기에서 드러난 것이다.
- 원인: 직접 설치한 앱은 다른 화면(권한 창·공유·링크·홈)을 거쳐 **떠날 때 보던 화면으로 돌아오기만 해도** 런처 액티비티가 아닌 화면이 재개돼 R5를 통과하고, 사용자 조작 기록이 거의 없어 R3도 통과한다.

## 3. 추가한 규칙

어느 하나라도 해당하면 정상 전환이다(R1~R5와 같음).

| 코드 | 조건 | 특징 |
|---|---|---|
| R6 | 다른 앱에서 넘어와, 이 앱이 전에 다른 앱에 넘길 때 보던 화면으로 돌아옴. 단 그때의 사용이 정상 판정으로 시작했어야 함 | F11 떠난 화면으로 복귀, F12 그 사용이 정상으로 시작 |
| R7 | 다른 앱이 멈추고 2초 안에, 다른 앱이 열 수 있는 화면(`exported`, 별칭이면 `targetActivity`)이 열림 (공유·링크 대상) | F13 공개 화면, F14 직전 앱이 멈춘 뒤 경과 |

- **사용 시작 판정**: 다른 앱에서 넘어온 전환의 판정을 그 앱 사용의 시작 판정으로 남긴다. 같은 앱 안 전환(R2)은 시작 판정을 바꾸지 않는다. 그래서 광고로 시작한 사용은 앱 안 화면을 옮겨도 정상이 되지 않고, 반복해서 뜨는 광고는 같은 화면이어도 R6에 걸리지 않는다. 보류로 시작한 사용도 정상으로 보지 않는다.
- **떠난 화면 기록**: 앱마다 최근 8개를 기억한다. 공유로 다른 앱 작업 위에 뜬 화면이 앱 자체 화면 기록을 밀어내지 않게 하려는 것이다(하나만 기억하면 공유 뒤 아이콘으로 다시 열 때 오탐이 났다).
- **구간을 넘어 유지**: 재부팅·시계 변경·공백으로 관측 구간을 새로 열어도 떠난 화면 기록은 넘긴다. 앱 작업은 재부팅 뒤에도 최근 앱에 남아 그 화면으로 다시 열리기 때문이다. 그때 보이던 화면도 떠난 화면으로 남기고, 구간 첫 전환처럼 직전 화면을 모를 때도 이 기록으로 복귀를 판정한다. 같은 ms 순서에 따라 기록이 갈리면 모든 경우에 기록이 있고 정상일 때만 정상으로 넘긴다.
- **첫 검사**: 설치 직후나 저장된 상태를 못 읽었을 때(이전 형식 포함)는 지난 하루치 기록으로 상태만 채우고, 그 판정은 저장하지 않는다(`scan_run.note = warmup <전환 수>`). 그 조회가 null이면 상태를 저장하지 않고 다음 검사에서 다시 채운다. 상태 없이 시작하면 최근 앱에서 다시 여는 앱마다 첫 번을 광고로 세고, 그 사용이 광고로 시작한 것으로 남아 이후 다시 열 때마다 광고로 센다(교체 설치 직후 실기기에서 네이버 2건으로 확인).
- **공개 화면 목록**: 검사마다 이번 조회에서 화면이 바뀐 앱만 `PackageManager.GET_ACTIVITIES`로 읽는다. 못 읽으면 공개 화면 없음으로 본다.

| 자료 | 정상 전환 | 기존 규칙 오탐 | 새 규칙 오탐 | 광고 (기존 → 새) |

- R1을 꺼도 남는 5건은 시스템 창이다(USB 연결 팝업, 내 디바이스 찾기 안내, 계정 확인 창, 앱 선택 창, 런처).

- 에뮬레이터 자료의 bgad 공개 화면은 매니페스트로 넣었다(`MainActivity`·`NormalActivity` exported, `AdActivity` 아님). 다른 패키지는 목록이 없어 공개 화면 없음으로 계산했다.

## 6. 한계·미확인

- **같은 자료로 만든 규칙이다.** 2절 오탐을 보고 규칙을 만들었으므로 4절은 독립 평가가 아니다. 쿠팡·웹툰 단계는 R6·R7을 처음 만든 뒤 모은 자료지만, 떠난 화면 기록 방식은 그 자료를 보고 고쳤다. 평가(T074)는 새 기기·새 앱으로 따로 한다.
- **우회 가능**: 광고 화면을 `exported`로 선언하면 R7, 사용자가 정상으로 쓰던 화면 클래스를 광고에 다시 쓰면 R6을 통과한다. 재현 앱과 광고 SDK의 광고 화면(`AdActivity`)은 exported가 아니다.
- **첫 검사 하루 밖**: 하루 넘게 쓰지 않은 앱의 작업이 최근 앱에 남아 있으면, 설치 뒤 처음 다시 열 때 광고로 셀 수 있고 그 뒤 같은 화면 복귀도 광고로 센다. 그 앱을 새로 실행(런처 화면)해 같은 화면을 다시 떠날 때까지 이어진다.
- **보지 못한 상황**: 로그인·결제 앱 왕복(E1·E2), 광고가 나오는 게임(약관 동의 전이라 못 함), 사용자 설치 앱의 알림 진입, 카카오톡처럼 공유 대상이 많은 앱.
- 판정기 판 표시: `symptom_event.detectorVersion = usage-fx0-r7`. 저장 상태 형식은 `fx1-draft`로 올렸다. 이전(`fx0-draft`) 상태는 복원하지 않고 첫 검사처럼 지난 하루치로 새로 채운다.

## 7. 재계산 방법

```bash
python3 testapps/poc/features/featx.py          # 사례
python3 testapps/poc/features/mutate.py         # 변형 시험
O=ml/data/poc/product_obs/scenario_auto_2026-11-17
python3 testapps/poc/features/eval_real.py --exported $O/s10.exported.csv $O/s10.launchers.csv $O/s10.events.csv
python3 testapps/poc/features/eval_real.py --exported $O/s10.exported.csv --no-system-filter $O/s10.launchers.csv $O/s10.events.csv
python3 testapps/poc/features/eval_real.py --exported <bgad 공개 화면 목록> ml/data/poc/launchers.csv $(find ml/data/poc -name '*events.csv' -not -path '*product_obs*')
# 기존 규칙: featx.py만 main(342f15f) 판으로 바꿔 같은 명령
```

- 사용 기록 수집: `testapps/usageprobe` 설치, 사용 기록 권한 허용 뒤 `DumpReceiver`(`--el from --el to --es out`)와 `LaunchersReceiver`(`launchers.csv`, `exported.csv`).
- 단계 진행 기록: `testapps/poc/product_scenario.sh`(사람이 단계마다 Enter, 단계 끝 7초 뒤 검사).
