# ADR-0003: 탐지의 중심을 설치 시점 분류에서 실행 중 증상 감지로 옮김

- **상태**: Accepted — 2026-10-14 (사용자 승인)
- **날짜**: 2026-10-14
- **결정자**: 최인규

## 맥락

- 해결 대상은 **앱 밖 광고**로 좁혀짐(2026-10-14 정정). 사용자가 직접 실행하지 않았는데 설치된 앱 때문에 폰 사용 중 광고가 수시로 뜨는 상황. 앱 안 전면 광고는 대상이 아님.
- 가족 사례([spec Q1](../../specs/001-mvp/spec.md), PR #5): 할머니 폰은 삼성 **디바이스 케어를 직접 눌러** 해결함. 기본 탑재 수단의 자동 탐지가 그 상황을 놓쳤음. 즉 차별점은 탐지 성능이 아니라 **(1) 누르지 않아도 늘 자동으로 감지하고, (2) 광고가 화면을 막아도 원인 앱을 짚어 가족에게 알리고, (3) 시니어가 한 번만 눌러 지우게 하는 경로**임.
- 현재 스펙은 **설치 시점 온디바이스 분류기**(FR-001~009)를 중심에 둠. 그런데:
  - 무작위 Play 앱 56개 관찰에서 앱 밖 광고를 내는 앱이 **0개**(T026). 설치 직후 분류기의 성능을 보여 줄 정답 앱이 사실상 없음. MH-1M은 낡았고 Play에서 삭제된 앱이 많음.
  - 기존 탐지 앱(AppWatch, Popup Ad Detector, 각 1천만+ 설치)이 이미 있고, 리뷰에 "보안 앱 여러 개 돌려도 못 찾음"이 나옴. 빈 자리는 **탐지 자체가 아니라 해석·조치·가족 연결**임.
- 따라서 "어떤 신호로 앱 밖 광고를 잡을 것인가"를 먼저 정해야 함.

## 기술 확인 (이 결정의 전제)

앱 밖 광고는 두 형태로 나뉘고, 각각 관측 가능성이 다름.

| 형태 | 구현 | 사용 기록(UsageStats)에 남는가 | 근거 |
|---|---|---|---|
| **액티비티형** | 전면 광고 액티비티를 배경에서 띄움 | **남음** — `ACTIVITY_RESUMED`(API 29+, `MOVE_TO_FOREGROUND`) 이벤트로 포그라운드 전환이 기록됨 | [1] |
| **오버레이형** | 다른 앱 위에 창을 겹쳐 그림(`TYPE_APPLICATION_OVERLAY`) | **안 남음** — 액티비티 생명주기가 아니라 창이라 포그라운드 이벤트가 없음 | [1] 추론 + 실험 미실시 |

- **연결 고리 — SYSTEM_ALERT_WINDOW("다른 앱 위에 그리기")**: Android 10+는 배경 앱의 액티비티 시작을 막지만, 이 권한을 가진 앱은 **면제** 대상임[2]. 오버레이형은 이 권한이 애초에 필수라 앱 밖 광고를 내는 앱이 매니페스트에 **요청**해 둔 경우가 많음. 단, 일반 앱은 다른 앱의 **허용 상태**를 조회할 수 없고(AppOps는 자기 앱만 확인 가능), 설치 시점에 읽을 수 있는 건 **요청(선언) 여부**뿐임(classifier.md §2, 근거 코드 `OVERLAY_PERMISSION`). 따라서 이 신호는 사전 경고 휴리스틱이며 보유 여부나 탐지 범위를 보장하지 않음.
- **실증**: AppWatch(사용 기록 권한, 1천만+ 설치)가 "지금 화면에 뜬 앱"을 사용 기록으로 짚어내며 운영 중. 액티비티형 감지가 실제로 동작함을 증명함.
- **접근성 경로는 MVP에서 안 씀**: 오버레이형까지 잡으려면 접근성 서비스가 필요하지만(Popup Ad Detector 방식), 비접근성 도구 앱은 Play의 별도 공개·명시적 동의·신고·심사 요건을 통과해야 하고, Android 17 고급 보호가 켜진 기기에서는 접근성 도구로 검증되지 않은 앱의 권한이 제한됨. 심사 통과 여부·지원 기기를 확정하기 전엔 기본 경로로 쓰지 않음(비목표·원칙 V와 일치).
- **정책 여유**: 사용 기록 권한은 Play 민감 권한 신고 목록에 없음. `QUERY_ALL_PACKAGES`는 백신 용도가 허용 예시지만, 핵심 기능에 전체 조회가 필요한 이유와 좁은 대안이 부족한 이유를 선언해야 함(권한 허용이 성인 가족 공유 승인은 아님). 한 앱 + 역할 선택(ADR-0002)이라 manifest·Play 선언은 런타임 역할로 분리되지 않음 → `QUERY_ALL_PACKAGES`·`isMonitoringTool` 선언은 **APK 전체(보호자 설치본 포함)에 적용**되고 모든 version code·track에 요구됨. 동일 bundle 유지 vs 역할별 분리는 출시 전 결정(spec Q5).

## 선택지

### 안 A: 지금대로 — 설치 시점 분류기 중심

- 장점: 이미 구현된 특징 추출기(T022)·MH-1M 스키마를 그대로 씀. 설치 즉시(실행 전) 경고 가능.
- 단점: **평가할 정답 앱이 없음**(0/56). 실제 앱 밖 광고 현상과 분류기 출력의 연결을 시연으로 보이기 어려움. 기존 탐지 앱과 차별점이 약함.

### 안 B: 실행 중 증상 감지 중심 + 분류기는 설치 시점 보조 (선택)

- **증상 감지(주)**: 사용 기록 권한으로 "시니어가 조작하지 않은 동안 포그라운드로 튀어나온 앱"을 귀속. "○○ 앱이 오늘 N번 전면 광고를 띄웠어요"를 근거로 가족에게 알림.
- **분류기(보조)**: 설치 시점에 `SYSTEM_ALERT_WINDOW` 요청 여부·광고 SDK 수·배경 시작 징후를 읽어 **사전 경고**. 사용 기록으로 안 보이는 **오버레이형의 보조 신호**가 됨(탐지 보장은 아님).
- 장점:
  - 사용자 목적(앱 밖 광고)과 증상이 직접 연결됨. 설치 경로·위장 여부와 무관.
  - 평가 가능: 재현 앱과 정상 앱 오탐 측정으로 성능을 보일 수 있음. T026 관찰 배치를 정상 앱 오탐 측정으로 재활용.
  - 두 작업이 상보적 — 분류기가 버려지지 않고 오버레이 공백을 메움.
- 단점:
  - **오버레이형 광고는 실행 중에 귀속 불가**(설치 시점 권한 신호로만 사전 경고). 알려진 한계로 남김.
  - "원인 앱 찾기" 자체는 기존 앱도 함 → 발표 포인트는 탐지가 아니라 **자동 귀속·근거 있는 가족 알림·시니어 한 번 터치**여야 함.
  - 8주차 베이스라인 보고 내용이 분류기 지표에서 증상 감지 지표로 바뀜.

### 안 C: 둘을 동등하게 병행

- 범위가 가장 넓음. 학기 내 두 축을 다 평가 수준으로 끌어올리기 부담. (완성도가 아니라 평가 범위 관점)

## 결정

**안 B.** 실행 중 증상 감지(사용 기록 권한)를 앱 밖 광고 대응의 주 경로로, 설치 시점 분류기를 사전 경고·오버레이 공백 보조로 둠.

## 결과

- 스펙 반영(이 PR에 포함): US11(증상 감지 → 가족 알림) 추가, FR-009를 주 신호로 승격 + FR-010~012 추가, FR-001~008을 분류기(보조)로 명시, US1에 보조 역할 주석, G2·SC-002를 증상 감지 기준으로 재작성, tasks T034~T036·T074 추가. **편집 구역은 #4(US10)·#5(가족 사례)가 건드리는 §2 문제 정의·§11 Q 표를 피해 배치**해 병합 충돌을 최소화함(#4·#5는 서로 Q1 줄이 겹침, 이 PR은 그 줄을 안 건드림).
- 평가 설계: 재현 앱(액티비티형)으로 recall, T026 정상 앱으로 FPR. 오버레이형은 커버리지 한계로 명시.
- [ADR-0001](0001-backend.md)·[ADR-0002](0002-guardian-app-packaging.md)의 가족 알림·승인·삭제 흐름은 그대로 재사용(알림을 띄우는 트리거만 "위험 판정"에서 "증상 감지"로 추가됨).

## 알려진 한계 · 미결

- 🔵 오버레이형 앱 밖 광고의 실행 중 귀속 방법(접근성 외). 현재는 설치 시점 권한 신호로만 사전 경고. 자체 가상 디스플레이·창 관리 신호 조사 필요.
- 🔵 사용 기록 이벤트로 "사용자 조작 없는 포그라운드 전환"과 "정상 알림 탭 후 전환"을 구분하는 휴리스틱의 오탐율 — 재현/정상 앱으로 측정 필요.
- 🔵 최종 "지우기"는 여전히 시니어가 눌러야 함(일반 앱 한계). 알림에서 삭제 화면 직행으로 단축.
