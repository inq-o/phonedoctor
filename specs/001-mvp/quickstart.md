# 검증 시나리오 (Quickstart)

- 구현이 spec을 만족하는지 손으로 확인하는 절차. 14주차 시연 대본의 뼈대
- 준비: 에뮬레이터 2대(시니어 `Pixel_8_API_35`, 보호자 두 번째 AVD) 또는 실기기 2대, 테스트 광고 앱 APK(`testapps/`)

## 시나리오 2 — 오탐 방지

- 정상 앱(카카오톡 등) APK 설치 → 알림 없음, S4 기록에 "안전"
- 보호자가 [괜찮은 앱이에요] → 같은 APK 재설치 → 다시 묻지 않음 (FR-007)

## 시나리오 3 — 실패 상황

| 상황 | 방법 | 기대 결과 |
|---|---|---|
| 오프라인 판정 | 시니어 기기 비행기 모드 → 광고 앱 설치 | 판정·시니어 알림 정상, 비행기 모드 해제 후 보호자 알림 |
| 보호자 2명 경합 | 보호자 기기 2대가 거의 동시에 다른 응답 | 먼저 도착한 것만 반영, 다른 쪽 "△△님이 먼저 답했어요" |
| 시니어 취소 | 시스템 창에서 [취소] | 보호자에게 "아직 안 지웠어요" |
| 연결 해제 | 시니어 S5 [연결 끊기] | 보호자 알림, 보호자 목록에서 사라짐 |
| 글꼴 200% | 시니어 기기 설정 → 글꼴 최대 | S1·S2·S3 잘림 없음 |

## 측정 기록 (constitution VII)

- 시나리오 1을 5회 반복해 아래를 `ml/runs/` 또는 `docs/measurements/`에 기록
  - 판정 지연(ms), 서버 → 보호자 알림 도착(초), 승인 → 시니어 알림 도착(초)
  - 기기 모델·OS 버전·앱 버전·모델 버전
