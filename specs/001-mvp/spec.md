## 1. 한 줄 요약

- 시니어 폰에 뜨는 광고를 **출처와 상관없이** 찾아 막는 앱. 출처는 두 갈래
  - **설치된 앱**(광고 앱·악성코드): 앱 밖 광고를 띄운 앱을 **사용 기록으로 짚어내고**(주 경로, US11), 설치 시점에는 기기 안의 AI가 **미리 경고**(보조, US1). 확인이 필요하면 **가족(보호자)에게 승인 요청**을 보내, 승인되면 시니어가 **큰 버튼 하나로 삭제**
  - **Chrome 사이트 알림**: 광고 알림을 보내는 사이트를 찾아 시니어가 **스위치 하나로 그 사이트 알림만 끄게** 함 (US10)

## 2. 문제 정의

- **누가**: 스마트폰을 혼자 관리하기 어려운 70대 이상 사용자, 그리고 떨어져 사는 성인 자녀
- **무엇이**: 광고·악성 앱이 설치돼 폰이 광고로 뒤덮이거나 정보가 새는데, 당사자는 원인 앱을 찾지도 지우지도 못함. 또는 사이트에서 "알림 허용"을 한 번 눌러 "바이러스 감염"·"당첨" 같은 광고 알림이 Chrome을 켜지 않아도 계속 옴
- **출처별 모습** (2026-10-12 정리)
  - 홈·잠금화면 전면 광고, 다른 앱 위 광고 → 거의 확실히 **설치된 앱**. 웹페이지는 다른 앱 위에 그릴 수 없음
  - 앱 푸시처럼 뜨는 광고 알림(알림 출처 "Chrome") → **사이트 알림**. 누르면 Chrome이 열리며 전면 광고 페이지
  - Chrome 안에서만 보이는 광고·강제 이동 → 사이트 자체. 앱으로 막을 수단이 정책상 없음(§4 비목표)
- **왜 지금 해결 안 되나**: 해결 수단(시티즌코난·Play Protect)은 있지만 **당사자가 그 수단에 도달하지 못함**
  - 탐지 앱은 사용자가 직접 실행해야 함
  - 보호자 관리 앱은 아동 계정 전제
  - Play 심사를 통과한 광고 도배 앱은 기존 탐지 대상 밖
  - 기기 자체 진단(삼성 디바이스 케어)도 자동 탐지가 놓치면 설정에서 직접 실행해야 하는데, 광고가 화면을 가려 그 메뉴까지 가기 어려움 (가족 사례)
- **근거**: 본인 가족 사례(앱 밖에서 수 초마다 뜨는 전면 광고로 폰 사용 불가, 디바이스 케어를 직접 실행해 해결), 2024 보이스피싱 피해 8,545억 원(+91%) — 계획서 [1]
- **가족 사례 확인 사항 (2026-10-13·14, 사용자 설명)**: 앱을 실행하지 않고 가만히 있어도 게임 중간 광고 같은 전면 광고가 약 5초마다 또는 더 짧은 간격으로 나타났음. 디바이스 케어가 자동으로는 조치하지 못해(자동 실행 안 됨) 직접 실행해야 했고, 설정까지 가는 동안에도 광고가 계속 떠서 어려웠음. 자세한 내용은 [research.md](research.md) "가족 사례의 관찰과 한계"
- 🔵 **미결 Q1**: 원인 앱 이름과 광고 표시 방식은 미확정이며, 원래 기기를 다시 확인하지는 않음. 앱 진단으로 해결됐으므로 설치 앱 원인 가능성이 높지만, Chrome 사이트 알림이 원인인 경우는 US10(알림 접근 미허용 시 FR-040 안내)으로 대응

## 3. 사용자 (Proto-persona)

| 구분 | 프로필 | 하는 일 | 바라는 것 | 못 견디는 것 |
|---|---|---|---|---|
| **시니어 (보호 대상)** | 70대 후반, 갤럭시 A 시리즈, 카카오톡·유튜브·사진만 사용, 글꼴 크게 설정 | 광고 속 "설치" 버튼을 누름 | 폰이 원래대로 돌아오는 것 | 모르는 말, 작은 글씨, 잘못 눌러 뭔가 망가질까 하는 불안 |
| **보호자** | 40~50대 성인 자녀, 원격 거주, 업무 중 알림 확인 | 명절에 폰을 고쳐 줌, 전화로 "그거 누르지 마" | 알림만 보고 10초 안에 판단 | 잦은 알림, 판단 근거 없는 경고 |
| **설치 대행자** | 20대 손주 또는 보호자 본인 | 처음 설치·연결을 대신 해 줌 | 5분 안에 설정 끝 | 시니어 폰에서 복잡한 권한 설정 |

- 🔶 **가정 A1**: 첫 설치·연결은 대부분 가족이 **시니어 폰을 직접 들고** 함 → 온보딩은 설치 대행자 기준으로 설계, 이후 화면은 시니어 기준
- 🔶 **가정 A2**: 시니어는 알림을 탭할 수는 있지만 설정 메뉴 탐색은 못 함

| ID | 목표 | 측정 |

|---|---|---|---|
| **앱 단위 FPR** | 설치 시점 분류기 (US1) | 테스트셋 정상 앱 중 RISK 판정 앱 수 ÷ 정상 앱 수 | ≤ 5% (G1·SC-001) |

| **기기·일당 오경고 수** | 가족이 받는 알림 | 정상 사용 기기 1대에서 하루 동안 보호자에게 간 잘못된 승인 요청 수. 이벤트 단위로 5%를 통과해도 한 정상 앱에 경고가 반복될 수 있어 따로 잼 | 측정 후 정함 🔶 |

## 5. 사용자 시나리오 (우선순위 순)

> 각 스토리는 단독으로 구현·시연 가능한 단위 (spec-kit 규칙)

### US1 — 새 앱 설치 감지 · 판정 (P1)

시니어가 광고를 눌러 앱을 설치하면, 폰주치의가 알아서 그 앱을 검사하고 위험하면 시니어에게 알린다.

> **ADR-0003**: 앱 밖 광고의 주 감지 경로는 US11(실행 중 증상 감지)로 옮김. US1(설치 시점 분류)은 **설치 즉시 사전 경고(보조)** 역할 — 특히 사용 기록에 안 남는 오버레이형 광고의 관측 지점.

- **우선순위 이유**: 설치 즉시(실행 전) 미리 경고할 수 있는 유일한 지점. "사용자가 직접 실행해야 함"이라는 기존 앱의 한계를 넘는 지점
- **단독 시연**: 보호자 연결 없이도 시니어 폰에 "확인이 필요한 앱이 있어요" 알림이 뜨는 것까지

**인수 조건**
1. **Given** 폰주치의 설치·권한 허용 완료, **When** 테스트용 광고 앱 APK 설치, **Then** 설치 후 판정까지 실측 p95 ≤ 30분 목표(NFR-02)로 판정, "위험"이면 알림 표시. WorkManager 15분은 최소 간격이라 Doze·제조사 최적화로 더 늦어질 수 있음
2. **Given** 정상 앱(카카오톡 등) 설치, **When** 판정, **Then** 알림 없음, 기록에만 "안전"
3. **Given** 기기 오프라인, **When** 앱 설치, **Then** 판정은 정상 수행, 보호자 요청은 온라인 복귀 후 전송
4. **Given** 이미 판정한 앱이 업데이트됨, **When** 버전 변경 감지, **Then** 재판정

### US11 — 앱 밖 광고 증상 감지 → 가족 알림 (P1, 주 경로)

시니어가 앱을 켜지 않았는데 광고가 뜨면, 폰주치의가 사용 기록으로 어느 앱이 띄웠는지 알아내 "○○ 앱이 오늘 N번 광고를 띄웠어요"를 가족에게 알린다.

- **우선순위 이유**: 사용자가 말한 실제 문제(앱 밖 광고)에 직접 대응하는 **주 경로**(ADR-0003). ID는 뒤 번호(US10이 US1 Chrome용으로 먼저 쓰임)지만 우선순위는 US1과 같은 P1이라 설치 감지(US1) 바로 뒤에 둠. 기존 앱(AppWatch 등)과의 차별점은 자동 귀속·근거 있는 가족 알림·시니어 한 번 터치
- **단독 시연**: 앱 밖 광고를 내는 앱 설치 → 홈에서 대기 → 폰주치의가 그 앱을 짚어 "확인이 필요해요" 알림

**인수 조건**
1. **Given** 사용 기록 권한 허용, **When** 사용자가 조작하지 않은 동안 앱이 포그라운드로 튀어나옴(`ACTIVITY_RESUMED`), **Then** 그 앱에 귀속해 횟수·시각을 로컬에 기록
2. **Given** 한 앱이 앱 밖 광고 기준을 넘음, **Then** US4 흐름으로 보호자에게 "○○ 앱이 오늘 N번 광고" 근거와 함께 승인 요청
3. **Given** 시니어가 직접 앱을 열어 쓴 뒤의 전환이나 정상 알림 탭, **Then** 광고로 세지 않음 (FR-012 휴리스틱)
4. **Given** 사용 기록 권한 미허용, **Then** 설치 시점 분류기(보조)만으로 동작하고, 홈에 권한 안내
5. **Given** 오버레이형 광고(사용 기록에 안 남음), **Then** 실행 중 귀속은 못 하지만 설치 시점 `SYSTEM_ALERT_WINDOW` 요청 여부로 사전 경고 (ADR-0003 한계)
6. **Given** 보호자가 [괜찮은 앱이에요]로 허용한 앱이 기준을 넘음, **Then** 승인 요청 대신 보호자에게 알림 전용 요청 1번(같은 (패키지, 서명, 버전) 조합당), 보호자 기록에 '경고 앱' 표시, 시니어 알림 없음 (FR-007)
7. **Given** 같은 앱의 요청이 열려 있는 동안 다른 날 또 기준을 넘음, **Then** 새 알림 없이 요청의 감지 근거를 최신 날짜·횟수와 "광고 뜬 날 N일"로 갱신 (FR-023)

### US2 — 첫 전체 검사 (P1)

설치 직후 이미 깔려 있는 앱을 전부 검사해 결과를 보여 준다.

- **우선순위 이유**: 할머니 폰처럼 **이미 감염된 상태**에서 설치하는 경우가 대부분
- **단독 시연**: 온보딩 마지막 단계에서 "앱 87개를 살펴봤어요. 확인할 앱 2개" 화면

**인수 조건**
1. **Given** 첫 실행, **When** 온보딩 완료, **Then** 사용자 설치 앱 전부 판정 (시스템 앱 제외), 진행률 표시
2. **Given** 앱 150개, **When** 전체 검사, **Then** 30초 이내 완료 (🔶 가정: 앱당 200ms)

### US3 — 보호자 연결 (P1)

설치 대행자가 시니어 폰에 뜬 QR을 보호자 폰으로 찍어 연결하고, 시니어가 "연결할게요"를 눌러 확정한다.

- **우선순위 이유**: 승인 흐름(US4)의 전제
- **단독 시연**: 두 기기에 서로 연결 상태 표시

**인수 조건**
1. **Given** 시니어 폰에 연결 코드 표시, **When** 보호자 앱에서 QR 스캔 또는 6자리 입력, **Then** 시니어 폰에 "○○님과 연결할까요?" 확인창
2. **Given** 시니어가 [연결할게요], **Then** 양쪽에 연결 완료 표시
3. **Given** 코드 발급 10분 경과, **When** 입력, **Then** "코드 시간이 지났어요. 새 코드를 받아 주세요"
4. **Given** 연결 상태, **When** 시니어가 설정에서 [연결 끊기], **Then** 즉시 해제, 보호자에게 "연결이 해제됐어요" 알림 (정책상 필수, 원칙 III)

### US4 — 보호자 승인 요청 · 응답 (P1)

위험 앱이 발견되면 보호자 폰에 알림이 가고, 보호자는 근거를 보고 [지우자고 하기] / [괜찮은 앱이에요] 중 하나를 고른다.

- **우선순위 이유**: 차별점 2(승인 경계)의 핵심. 오탐 책임을 모델이 혼자 지지 않게 함
- **단독 시연**: 보호자 폰 알림 → 상세 → 응답 → 시니어 폰에 결과 도착

**인수 조건**
1. **Given** 연결된 보호자 1명 이상, **When** "위험" 판정, **Then** 30초 안에 보호자 알림 (FCM 정상 시)
2. **Given** 보호자 알림 탭, **Then** 앱 이름·아이콘·설치 경로·설치 시각·근거 3개·스토어 링크 표시
3. **Given** 보호자 2명, **When** 둘이 다른 응답, **Then** 먼저 도착한 응답만 반영, 나중 보호자에게 "△△님이 먼저 답했어요"
4. **Given** 보호자가 24시간 무응답, **Then** 보호자에게 1회 재알림, 48시간이면 시니어 화면에 "가족에게 전화해 보세요" 표시 (자동 삭제 없음)
5. **Given** 보호자가 [괜찮은 앱이에요], **Then** 해당 앱·버전을 이 기기 허용 목록에 추가, 같은 버전은 다시 묻지 않음

### US5 — 시니어 삭제 유도 (P1)

보호자가 [지우자고 하기]를 누르면, 시니어 폰에 알림이 오고, 탭하면 큰 화면에서 [지우기] 한 번으로 시스템 삭제창까지 간다.

- **우선순위 이유**: 실제 문제 해결 지점. 계획서 핵심 지표 G6
- **단독 시연**: 시니어 폰 알림 → 지우기 → 시스템 확인 → "지웠어요"

**인수 조건**
1. **Given** 보호자 승인 도착, **Then** 시니어 폰에 "딸 ○○님이 이 앱을 지우자고 했어요" 알림
2. **Given** 알림 탭, **Then** 앱 상세 화면, 주요 버튼 [이 앱 지우기] 1개
3. **Given** [이 앱 지우기], **Then** 시스템 삭제 확인창 표시 → 확인 시 삭제 → "지웠어요" 화면 → 보호자에게 결과 전송
4. **Given** 시니어가 시스템 확인창에서 취소, **Then** 보호자에게 "아직 안 지웠어요" 전송, 하루 뒤 시니어에게 1회 재안내

### US10 — Chrome 사이트 광고 알림 끄기 (P1)

사이트가 보내는 광고 알림이 계속 오면, 폰주치의가 어느 사이트인지 찾아 시니어가 스위치 하나로 그 사이트 알림만 끄게 한다.

- **우선순위 이유**: 시니어 폰의 흔한 광고 경로인데 앱 판정(US1)으로는 안 잡힘. 기존 대응은 "Chrome > 설정 > 사이트 설정 > 알림" 메뉴 탐색이라 가정 A2(설정 탐색 불가)에 걸림
- **단독 시연**: 테스트 사이트 알림 허용 → 광고 알림 수신 → 폰주치의 알림 → 탭 → 스위치 끄기 → 이후 그 사이트 알림 안 옴
- **동작 근거** (2026-10-12 에뮬레이터 확인, Chrome 130 · Android 15)
  - Chrome은 사이트마다 알림 채널을 따로 만든다. 채널 ID `web:https://<사이트>;<숫자>`
  - `Settings.ACTION_CHANNEL_NOTIFICATION_SETTINGS` + Chrome 패키지 + 채널 ID로 **그 사이트 하나의 설정 화면이 바로 열리고**, 스위치 하나("알림 표시")만 있음
  - 채널을 끄면 Chrome이 사이트 알림 권한 자체를 해제로 인식(사이트가 다시 보내려면 재허용 필요)
- **필요 권한**: 알림 접근(`NotificationListenerService`) — 사용자가 설정에서 직접 허용하는 특수 권한. 미허용이면 FR-040 안내 화면으로 대신함

**인수 조건**
1. **Given** 알림 접근 허용, **When** Chrome 사이트 알림 수신, **Then** 채널 ID에서 사이트 주소를 뽑아 사이트별 수신 기록(로컬)
2. **Given** 한 사이트가 광고 알림 기준(FR-051)을 넘음, **When** 판정, **Then** 시니어에게 "○○ 사이트가 광고 알림을 보내고 있어요. 끌까요?" 알림 1회
3. **Given** 시니어가 알림을 탭, **Then** 그 사이트 채널 설정 화면이 바로 열림. 끄고 돌아오면 "껐어요" 화면
4. **Given** 뉴스·은행 등 시니어가 허용 목록에 넣은 사이트, **Then** 다시 묻지 않음
5. **Given** 알림 내용, **Then** 기기 밖으로 보내지 않음. 보호자에게도 보내지 않음(원칙 III, 스토커웨어 정책)

### US6 — 판정 근거를 쉬운 말로 (P2)

"광고 SDK 7개, 다른 앱 위에 그리기 권한" 같은 근거를 시니어용·보호자용 문장으로 바꿔 보여 준다.

- **인수 조건**: 근거 코드마다 시니어 문장(해요체, 전문용어 없음)·보호자 문장(구체 수치 포함) 2종 제공. 기기가 Gemini Nano를 지원하면 문장 다듬기에 ML Kit Prompt API 사용, 미지원 기기는 템플릿 문장

### US7 — 오탐 신고 (P2)

보호자가 "정상 앱이에요"라고 응답하면 익명 피드백으로 모델 개선에 쓴다.

- **인수 조건**: 패키지명·버전·모델 버전·근거 코드만 전송. 기기 ID·사용자 정보 없음. 설정에서 끌 수 있음

### US8 — 강력 모드 (Device Owner) (P3)

공장 초기화한 폰을 QR로 프로비저닝하면, 보호자 승인 즉시 앱을 **정지(suspend)** 하고, 출처를 알 수 없는 앱 설치를 막는다.

- **인수 조건**: 승인 시 `setPackagesSuspended`, 설정에서 `DISALLOW_INSTALL_UNKNOWN_SOURCES` 켜기·끄기, 정지된 앱 목록에서 해제 가능
- ⚠️ 공장 초기화가 필요해 **기존 사용 중인 폰엔 적용 불가** → 시연용 별도 기기로만

### US9 — 주간 리포트 · 구독 (P3)

보호자에게 주 1회 "이번 주 앱 3개 설치, 모두 안전" 요약. 유료 구독(보호자 결제)으로 보호자 2명 이상·강력 모드 제공.

## 6. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 시스템 앱·제조사 사전 설치 앱 | 판정 대상 제외 (`FLAG_SYSTEM`). 업데이트된 시스템 앱도 제외 |
| 판정 직후 시니어가 직접 앱 삭제 | 요청 상태 `resolved_by_user`, 보호자 알림 갱신 |
| 같은 앱 재설치 | 허용 목록에 있으면 판정만 기록, 없으면 새 요청 |
| 허용한 앱이 나중에 광고를 띄움 | 승인 요청 대신 알림 전용 요청 1번, 보호자 기록에 '경고 앱'. 앱이 업데이트되면 버전이 달라 허용 목록에서 빠지므로 원래 승인 흐름 (FR-007) |
| 요청이 열린 채 며칠째 광고 | 새 알림 없이 근거만 갱신. 재알림은 FR-026(`kind: notice`는 재알림 없음), 둘 다 7일 뒤 `expired` (FR-023) |
| 연결된 보호자 없음 | 시니어 화면에만 표시, "가족을 연결하면 같이 확인할 수 있어요" |
| 보호자 앱 알림 꺼짐 | 연결 화면에서 경고. 서버는 알림 실패 시 24시간 재시도 대신 재알림 일정에 합침 |
| FCM 미도착 (제조사 배터리 최적화) | 앱 실행 시 서버에서 대기 중 요청 당겨오기(pull) |
| 위장 앱 (이름·아이콘이 "카카오톡") | 서명 인증서가 원본과 다르면 근거 코드 `IMPERSONATION` (P2) |
| 폰 교체·초기화 | 연결 코드 재발급으로 재연결. 서버의 이전 기기 링크는 90일 후 삭제 |
| 고급 보호 모드 켜진 기기 | `AdvancedProtectionManager`로 감지, 사이드로딩 차단 상태를 홈에 표시 |
| 삼성 인터넷 등 다른 브라우저의 사이트 알림 | 채널 구조 미확인(🔵 Q7). 확인 전에는 US10 범위에서 제외 (알림 권한 미허용 대체 경로인 FR-040과는 별개) |
| 정상 사이트(뉴스·은행)의 알림 | 키워드에 안 걸리면 묻지 않음. 물었는데 시니어가 "괜찮아요"를 누르면 허용 목록 |
| 알림 접근 권한을 나중에 끔 | 홈에 "광고 알림 찾기가 꺼져 있어요" 표시, 앱 판정(US1)은 계속 동작 |
| 앱 150개 이상 | 전체 검사는 WorkManager 백그라운드 작업으로 분할 |

## 7. 기능 요구사항 (FR)

> P0 = 없으면 출시 못 함 / P1 = 학기 내 목표 / P2 = 구조만 대비

### 감지 · 판정

> 탐지는 두 층 — **실행 중 증상 감지(주, 사용 기록)**로 앱 밖 광고를 귀속(FR-009~012)하고, **설치 시점 분류기(보조)**로 사전 경고(FR-001~008). [ADR-0003](../../docs/adr/0003-detection-approach.md)

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-001 | 사용자 설치 앱 목록과 각 앱의 권한·컴포넌트·설치 출처·서명을 기기 안에서 읽어야 한다 | P0 |
| FR-002 | 새 설치·업데이트를 `getChangedPackages` 순번 비교로 감지해야 한다 (주기 작업 + 앱 실행 시 + 프로세스 생존 중 동적 리시버) | P0 |
| FR-003 | 앱마다 특징 벡터를 만들고 온디바이스 모델로 안전/주의/위험 3단계와 점수를 산출해야 한다 | P0 |
| FR-004 | 판정마다 상위 근거 코드 최대 3개를 함께 산출해야 한다 | P0 |
| FR-005 | 컴포넌트 이름을 광고 SDK 규칙(LibChecker-Rules 기반, 광고 태그 직접 추가)과 대조해야 한다 | P0 |
| FR-006 | 판정 결과·모델 버전·점수·근거·처리 결과를 로컬 DB에 남겨야 한다 | P0 |
| FR-007 | 허용 목록에 있는 (패키지, 서명, 버전) 조합은 출처(설치 시점 판정·증상 감지)와 상관없이 다시 승인을 요청하지 않아야 한다. 단 허용한 앱이 증상 기준(FR-010)을 넘으면 '경고 앱'으로 기록하고, 보호자에게 승인 버튼 없는 알림 전용 요청(openapi `kind: notice`)을 같은 조합당 1번만 보낸다 | P0 |
| FR-008 | 모델 파일을 앱 업데이트 없이 교체할 수 있어야 한다 (서버 메타데이터 + SHA-256 검증) | P1 |
| FR-009 | 사용 기록 권한(UsageStats)으로 사용자가 조작하지 않은 동안 포그라운드로 전환된 앱을 감지해 앱별로 귀속해야 한다 (주 경로, ADR-0003). 권한 미허용 시 설치 시점 분류기(보조)만으로 동작해야 한다 | P1 |
| FR-010 | 귀속한 앱별로 앱 밖 광고 추정 횟수·시각을 로컬에 기록하고 "○○ 앱이 오늘 N번" 근거를 만들어야 한다 | P1 |
| FR-011 | 설치 시점 분류기는 `SYSTEM_ALERT_WINDOW`("다른 앱 위에 그리기") **요청(선언) 여부**를 사전 경고 신호로 써야 한다(일반 앱은 허용 상태를 조회 못 함, classifier.md §2) — 사용 기록에 안 남는 오버레이형 광고의 보조 신호, 탐지 보장은 아님 (ADR-0003) | P1 |
| FR-012 | 사용자 조작 직후 전환(정상 알림 탭 등)과 조작 없는 전환을 구분하는 휴리스틱을 두고, 그 오탐을 평가셋으로 측정해야 한다 | P1 |

## 9. 핵심 개체

- **Device**: 설치된 폰주치의 인스턴스. 역할 `protected`(시니어) / `guardian`(보호자)
- **Link**: 시니어 기기 ↔ 보호자 기기 연결. 상태 `pending` → `active` → `revoked`
- **InstalledApp**: 시니어 기기의 앱 스냅샷 (로컬 전용, 서버 전송 안 함)
- **Verdict**: 앱 1개에 대한 설치 시점 판정 (로컬)
- **SymptomEvent**: 조작 없는 포그라운드 전환 1건을 앱에 귀속한 기록 (로컬 전용, 서버 전송 안 함)
- **Alert**: 위험 판정 또는 증상 감지 기준 초과 1건에 대한 승인 요청 (서버). 출처 `install_scan` / `symptom`. 종류 `approval`(승인 요청) / `notice`(허용한 앱의 알림 전용). 상태 `open` → `decided` → `resolved`
- **Decision**: 보호자 응답
- 상세: [data-model.md](data-model.md)
