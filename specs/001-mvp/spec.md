## 1. 한 줄 요약

- 시니어 폰에 새로 설치된 앱을 **기기 안의 AI가 판정**하고, 위험하면 **가족(보호자)에게 승인 요청**을 보내, 승인되면 시니어가 **큰 버튼 하나로 삭제**하도록 돕는 앱

## 2. 문제 정의

- **누가**: 스마트폰을 혼자 관리하기 어려운 70대 이상 사용자, 그리고 떨어져 사는 성인 자녀
- **무엇이**: 광고·악성 앱이 설치돼 폰이 광고로 뒤덮이거나 정보가 새는데, 당사자는 원인 앱을 찾지도 지우지도 못함
- **왜 지금 해결 안 되나**: 해결 수단(시티즌코난·Play Protect)은 있지만 **당사자가 그 수단에 도달하지 못함**
  - 탐지 앱은 사용자가 직접 실행해야 함
  - 보호자 관리 앱은 아동 계정 전제
  - Play 심사를 통과한 광고 도배 앱은 기존 탐지 대상 밖
- **근거**: 본인 가족 사례(광고 앱으로 폰 사용 불가), 2024 보이스피싱 피해 8,545억 원(+91%) — 계획서 [1]
- 🔵 **미결 Q1**: 할머니 폰 광고의 원인이 설치 앱인지 **Chrome 사이트 알림**인지 미확인. 후자면 앱 분류기로 안 잡힘 → FR-040으로 별도 대응

## 3. 사용자 (Proto-persona)

| 구분 | 프로필 | 하는 일 | 바라는 것 | 못 견디는 것 |
|---|---|---|---|---|
| **시니어 (보호 대상)** | 70대 후반, 갤럭시 A 시리즈, 카카오톡·유튜브·사진만 사용, 글꼴 크게 설정 | 광고 속 "설치" 버튼을 누름 | 폰이 원래대로 돌아오는 것 | 모르는 말, 작은 글씨, 잘못 눌러 뭔가 망가질까 하는 불안 |
| **보호자** | 40~50대 성인 자녀, 원격 거주, 업무 중 알림 확인 | 명절에 폰을 고쳐 줌, 전화로 "그거 누르지 마" | 알림만 보고 10초 안에 판단 | 잦은 알림, 판단 근거 없는 경고 |
| **설치 대행자** | 20대 손주 또는 보호자 본인 | 처음 설치·연결을 대신 해 줌 | 5분 안에 설정 끝 | 시니어 폰에서 복잡한 권한 설정 |

- 🔶 **가정 A1**: 첫 설치·연결은 대부분 가족이 **시니어 폰을 직접 들고** 함 → 온보딩은 설치 대행자 기준으로 설계, 이후 화면은 시니어 기준
- 🔶 **가정 A2**: 시니어는 알림을 탭할 수는 있지만 설정 메뉴 탐색은 못 함

## 4. 목표 / 비목표

### 목표 (계획서 지표 그대로)

| ID | 목표 | 측정 |
|---|---|---|
| G1 | 오탐률(FPR) ≤ 5% | 별도 테스트셋의 정상 앱 중 "위험" 판정 비율 |
| G2 | 광고 도배 앱 탐지율(Recall) ≥ 90% | 테스트셋 광고·악성 앱 중 "위험" 판정 비율 |

## 5. 사용자 시나리오 (우선순위 순)

> 각 스토리는 단독으로 구현·시연 가능한 단위 (spec-kit 규칙)

### US1 — 새 앱 설치 감지 · 판정 (P1)

시니어가 광고를 눌러 앱을 설치하면, 폰주치의가 알아서 그 앱을 검사하고 위험하면 시니어에게 알린다.

- **우선순위 이유**: 이것 없이는 나머지 흐름이 시작되지 않음. "사용자가 직접 실행해야 함"이라는 기존 앱의 한계를 넘는 지점
- **단독 시연**: 보호자 연결 없이도 시니어 폰에 "확인이 필요한 앱이 있어요" 알림이 뜨는 것까지

**인수 조건**
1. **Given** 폰주치의 설치·권한 허용 완료, **When** 테스트용 광고 앱 APK 설치, **Then** 15분 안에 판정 완료, "위험"이면 알림 표시
2. **Given** 정상 앱(카카오톡 등) 설치, **When** 판정, **Then** 알림 없음, 기록에만 "안전"
3. **Given** 기기 오프라인, **When** 앱 설치, **Then** 판정은 정상 수행, 보호자 요청은 온라인 복귀 후 전송
4. **Given** 이미 판정한 앱이 업데이트됨, **When** 버전 변경 감지, **Then** 재판정

### US2 — 첫 전체 검사 (P1)

설치 직후 이미 깔려 있는 앱을 전부 검사해 결과를 보여 준다.

- **우선순위 이유**: 할머니 폰처럼 **이미 감염된 상태**에서 설치하는 경우가 대부분
- **단독 시연**: 온보딩 마지막 단계에서 "앱 87개를 살펴봤어요. 확인할 앱 2개" 화면

**인수 조건**
1. **Given** 첫 실행, **When** 온보딩 완료, **Then** 사용자 설치 앱 전부 판정 (시스템 앱 제외), 진행률 표시
2. **Given** 앱 150개, **When** 전체 검사, **Then** 30초 이내 완료 (🔶 가정: 앱당 200ms)

### US3 — 보호자 연결 (P1)

설치 대행자가 시니어 폰에 뜬 QR을 보호자 폰으로 찍어 연결하고, 시니어가 "연결할게요"를 눌러 확정한다.

- **우선순위 이유**: 승인 흐름(US4)의 전제
- **단독 시연**: 두 기기에 서로 연결 상태 표시

**인수 조건**
1. **Given** 시니어 폰에 연결 코드 표시, **When** 보호자 앱에서 QR 스캔 또는 6자리 입력, **Then** 시니어 폰에 "○○님과 연결할까요?" 확인창
2. **Given** 시니어가 [연결할게요], **Then** 양쪽에 연결 완료 표시
3. **Given** 코드 발급 10분 경과, **When** 입력, **Then** "코드 시간이 지났어요. 새 코드를 받아 주세요"
4. **Given** 연결 상태, **When** 시니어가 설정에서 [연결 끊기], **Then** 즉시 해제, 보호자에게 "연결이 해제됐어요" 알림 (정책상 필수, 원칙 III)

### US4 — 보호자 승인 요청 · 응답 (P1)

위험 앱이 발견되면 보호자 폰에 알림이 가고, 보호자는 근거를 보고 [지우자고 하기] / [괜찮은 앱이에요] 중 하나를 고른다.

- **우선순위 이유**: 차별점 2(승인 경계)의 핵심. 오탐 책임을 모델이 혼자 지지 않게 함
- **단독 시연**: 보호자 폰 알림 → 상세 → 응답 → 시니어 폰에 결과 도착

**인수 조건**
1. **Given** 연결된 보호자 1명 이상, **When** "위험" 판정, **Then** 30초 안에 보호자 알림 (FCM 정상 시)
2. **Given** 보호자 알림 탭, **Then** 앱 이름·아이콘·설치 경로·설치 시각·근거 3개·스토어 링크 표시
3. **Given** 보호자 2명, **When** 둘이 다른 응답, **Then** 먼저 도착한 응답만 반영, 나중 보호자에게 "△△님이 먼저 답했어요"
4. **Given** 보호자가 24시간 무응답, **Then** 보호자에게 1회 재알림, 48시간이면 시니어 화면에 "가족에게 전화해 보세요" 표시 (자동 삭제 없음)
5. **Given** 보호자가 [괜찮은 앱이에요], **Then** 해당 앱·버전을 이 기기 허용 목록에 추가, 같은 버전은 다시 묻지 않음

### US5 — 시니어 삭제 유도 (P1)

보호자가 [지우자고 하기]를 누르면, 시니어 폰에 알림이 오고, 탭하면 큰 화면에서 [지우기] 한 번으로 시스템 삭제창까지 간다.

- **우선순위 이유**: 실제 문제 해결 지점. 계획서 핵심 지표 G6
- **단독 시연**: 시니어 폰 알림 → 지우기 → 시스템 확인 → "지웠어요"

**인수 조건**
1. **Given** 보호자 승인 도착, **Then** 시니어 폰에 "딸 ○○님이 이 앱을 지우자고 했어요" 알림
2. **Given** 알림 탭, **Then** 앱 상세 화면, 주요 버튼 [이 앱 지우기] 1개
3. **Given** [이 앱 지우기], **Then** 시스템 삭제 확인창 표시 → 확인 시 삭제 → "지웠어요" 화면 → 보호자에게 결과 전송
4. **Given** 시니어가 시스템 확인창에서 취소, **Then** 보호자에게 "아직 안 지웠어요" 전송, 하루 뒤 시니어에게 1회 재안내

### US6 — 판정 근거를 쉬운 말로 (P2)

"광고 SDK 7개, 다른 앱 위에 그리기 권한" 같은 근거를 시니어용·보호자용 문장으로 바꿔 보여 준다.

- **인수 조건**: 근거 코드마다 시니어 문장(해요체, 전문용어 없음)·보호자 문장(구체 수치 포함) 2종 제공. 기기가 Gemini Nano를 지원하면 문장 다듬기에 ML Kit Prompt API 사용, 미지원 기기는 템플릿 문장

### US7 — 오탐 신고 (P2)

보호자가 "정상 앱이에요"라고 응답하면 익명 피드백으로 모델 개선에 쓴다.

- **인수 조건**: 패키지명·버전·모델 버전·근거 코드만 전송. 기기 ID·사용자 정보 없음. 설정에서 끌 수 있음

### US8 — 강력 모드 (Device Owner) (P3)

공장 초기화한 폰을 QR로 프로비저닝하면, 보호자 승인 즉시 앱을 **정지(suspend)** 하고, 출처를 알 수 없는 앱 설치를 막는다.

- **인수 조건**: 승인 시 `setPackagesSuspended`, 설정에서 `DISALLOW_INSTALL_UNKNOWN_SOURCES` 켜기·끄기, 정지된 앱 목록에서 해제 가능
- ⚠️ 공장 초기화가 필요해 **기존 사용 중인 폰엔 적용 불가** → 시연용 별도 기기로만

### US9 — 주간 리포트 · 구독 (P3)

보호자에게 주 1회 "이번 주 앱 3개 설치, 모두 안전" 요약. 유료 구독(보호자 결제)으로 보호자 2명 이상·강력 모드 제공.

## 6. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 시스템 앱·제조사 사전 설치 앱 | 판정 대상 제외 (`FLAG_SYSTEM`). 업데이트된 시스템 앱도 제외 |
| 판정 직후 시니어가 직접 앱 삭제 | 요청 상태 `resolved_by_user`, 보호자 알림 갱신 |
| 같은 앱 재설치 | 허용 목록에 있으면 판정만 기록, 없으면 새 요청 |
| 연결된 보호자 없음 | 시니어 화면에만 표시, "가족을 연결하면 같이 확인할 수 있어요" |
| 보호자 앱 알림 꺼짐 | 연결 화면에서 경고. 서버는 알림 실패 시 24시간 재시도 대신 재알림 일정에 합침 |
| FCM 미도착 (제조사 배터리 최적화) | 앱 실행 시 서버에서 대기 중 요청 당겨오기(pull) |
| 위장 앱 (이름·아이콘이 "카카오톡") | 서명 인증서가 원본과 다르면 근거 코드 `IMPERSONATION` (P2) |
| 폰 교체·초기화 | 연결 코드 재발급으로 재연결. 서버의 이전 기기 링크는 90일 후 삭제 |
| 고급 보호 모드 켜진 기기 | `AdvancedProtectionManager`로 감지, 사이드로딩 차단 상태를 홈에 표시 |
| 앱 150개 이상 | 전체 검사는 WorkManager 백그라운드 작업으로 분할 |

## 7. 기능 요구사항 (FR)

> P0 = 없으면 출시 못 함 / P1 = 학기 내 목표 / P2 = 구조만 대비

### 감지 · 판정

| ID | 요구사항 | 우선 |
|---|---|---|
| FR-001 | 사용자 설치 앱 목록과 각 앱의 권한·컴포넌트·설치 출처·서명을 기기 안에서 읽어야 한다 | P0 |
| FR-002 | 새 설치·업데이트를 `getChangedPackages` 순번 비교로 감지해야 한다 (주기 작업 + 앱 실행 시 + 프로세스 생존 중 동적 리시버) | P0 |
| FR-003 | 앱마다 특징 벡터를 만들고 온디바이스 모델로 안전/주의/위험 3단계와 점수를 산출해야 한다 | P0 |
| FR-004 | 판정마다 상위 근거 코드 최대 3개를 함께 산출해야 한다 | P0 |
| FR-005 | 컴포넌트 이름을 광고 SDK 규칙(LibChecker-Rules 기반, 광고 태그 직접 추가)과 대조해야 한다 | P0 |
| FR-006 | 판정 결과·모델 버전·점수·근거·처리 결과를 로컬 DB에 남겨야 한다 | P0 |
| FR-007 | 허용 목록에 있는 (패키지, 서명, 버전) 조합은 다시 요청하지 않아야 한다 | P0 |
| FR-008 | 모델 파일을 앱 업데이트 없이 교체할 수 있어야 한다 (서버 메타데이터 + SHA-256 검증) | P1 |

## 9. 핵심 개체

- **Device**: 설치된 폰주치의 인스턴스. 역할 `protected`(시니어) / `guardian`(보호자)
- **Link**: 시니어 기기 ↔ 보호자 기기 연결. 상태 `pending` → `active` → `revoked`
- **InstalledApp**: 시니어 기기의 앱 스냅샷 (로컬 전용, 서버 전송 안 함)
- **Verdict**: 앱 1개에 대한 판정 (로컬)
- **Alert**: 위험 판정 1건에 대한 승인 요청 (서버). 상태 `open` → `decided` → `resolved`
- **Decision**: 보호자 응답
- 상세: [data-model.md](data-model.md)
