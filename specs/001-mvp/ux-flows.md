# UI/UX 흐름

- 대상: 시니어 기기(보호 대상) · 보호자 기기 · 설치 대행자(첫 설정)
- 근거·출처: [research.md](research.md) §3 디자인 기준
- 화면 ID 규칙: `S`=시니어, `G`=보호자, `O`=온보딩(공통)
- **Figma 시안(11화면, 2026-10-03)**: https://www.figma.com/design/UcNiV8MvfXp6NazfkBB5KG — 토큰 변수·텍스트 스타일·컴포넌트(시니어/보호자 버튼, 상태 원, 상태 칩) 포함.

## 1. 설계 원칙

| # | 원칙 | 적용 | 근거 |
|---|---|---|---|
| 1 | 한 화면, 주요 행동 1개 | 시니어 화면의 채운 버튼은 1개. 나머지는 **테두리 버튼**이나 테두리 메뉴 칸(글자만 있는 버튼 금지). 버튼이 2개면 반씩 가로로 나란히(아래 "버튼 쌍"). 예외: S1′는 앱 카드가 주요 행동이라 채운 버튼이 없음, 기다리는 화면(연결 코드, 보호자 답 대기)은 채운 버튼 없이 아래쪽에 [나중에]를 반드시 둠 (2026-11-25) | 서울시 고령층 접근성 표준 지침 2·3 (필수 요소, 단순한 구조) · 늘다 관찰: 시니어는 글자로 된 UI를 누를 수 있다고 인식하지 않음 [R1] |
| 2 | 전화로 설명할 수 있는 화면 | 색·위치·버튼 문구를 고정 ("아래쪽 빨간 버튼 누르세요"). 시니어 화면에서 **Dynamic Color 끔** | 보호자가 전화로 안내하는 상황 (페르소나) |
| 3 | 겁주지 않기 | "위험!", "해킹" 대신 "확인이 필요한 앱이 있어요". 결정은 권유형 | 토스 라이팅 원칙 6 (Suggest than force), 지침 10 (심리적 부담) |
| 4 | 되돌릴 수 있게 | 허용 → 나중에 다시 검사 가능, 연결 해제 → 다시 연결 가능, 삭제 전 시스템 확인창 | 지침 9 (오류 예방·복구) |
| 5 | 상태가 보이게 | 홈 맨 위에 상태 문장 1개 + 마지막 검사 시각 | 지침 5 (시스템 상태 가시성) |
| 6 | 시간 제한 없음 | 시니어 화면에 타이머·자동 닫힘 없음 (연결 코드 10분은 보호자 화면 쪽에서 재발급 유도) | 고령자 디자인 체크리스트(ISO 25556) 금지 항목 |
| 7 | 시스템 설정 존중 | 시스템 글꼴·글꼴 크기 그대로 사용(삼성 사용자 글꼴 포함), sp 단위, 200%에서 잘림 없음 | Android 14 비선형 글꼴 배율 최대 200% |
| 8 | 누르는 건 아래, 읽는 건 위 | 시니어 화면의 버튼은 화면 아래쪽에 고정. 홈의 누르는 영역(메뉴 칸, 광고 찾기 꺼짐의 [켜러 가기])은 아래쪽에 두되 고정하지 않음(아래 §2 예외). 위쪽은 상태 문장·설명. 위쪽 구석에 작은 버튼(설정 등)을 두지 않음 | 삼성 One UI 화면 구성(보기 영역/조작 영역), 엄지 닿는 범위 [R1] |
| 9 | 지금 몇 단계인지 | 온보딩 화면 맨 위에 "2/4" 대신 문장으로 "4단계 중 2단계" | 늘다 관찰: 어떤 단계에 있는지 인식하지 못함 [R1] |

**보호자 화면** (2026-11-25): 보호자는 스마트폰을 보통으로 쓰는 사람이라 흔한 앱 모양을 따른다. 위 막대에 뒤로(←), 홈 오른쪽 위에 설정 톱니. 원칙 1·8(시니어 전용)은 적용하지 않고 "화면당 가장 강조된 버튼 하나"(KRDS)만 지킨다. 목록은 흰 띠 + 구분선으로 묶고, 같은 테두리 카드를 늘어놓지 않는다. 강조색은 주요 행동과 상태에만 쓴다. 빨강은 시니어 폰의 실제 [지우기]에만 쓰고, 보호자의 [삭제 요청]은 파랑(primary) (§8 R10~R13)

**버튼 쌍** (2026-11-25): 시니어 화면에서 고르는 버튼이 2개면 화면 아래에 반씩 가로로 둔다. 왼쪽은 물러나기([나중에], [안 할래요]), 오른쪽은 주요 행동. 시스템 삭제 창 [취소 | 확인]과 같은 순서라 이어서 봐도 헷갈리지 않는다. 글꼴을 키워 한 줄에 안 들어가면 세로로 쌓고 주요 버튼을 아래에 둔다(Android 대화상자와 같은 방식). S2·S3·연결 코드·G2에 공통 적용

## 2. 정보 구조 (IA)

```
폰주치의 (한 앱, 첫 실행에서 역할 선택 — ADR-0002 안 A 기준)
├─ O 온보딩 (공통)
│   ├─ O1 역할 선택: "이 폰을 지켜요" / "가족 폰을 지켜요"
│   └─ (역할별 분기)
│
├─ 시니어 모드
│   ├─ O-S1 무엇을 하는 앱인지 (공개 고지, FR-041)
│   ├─ O-S2 권한: 알림 → 사용 기록 (앱 밖 광고 찾기, 주 경로) → (선택) 알림 접근 (사이트 광고 알림, US10)
│   ├─ O-S3 첫 전체 검사 (US2)
│   ├─ O-S4 가족 연결 코드·QR (US3)  ← 건너뛰기 가능
│   ├─ S1 홈
│   ├─ S2 앱 상세 · 삭제 유도 (US5)
│   ├─ S3 연결 확인 "○○님과 연결할까요?"
│   ├─ S4 검사 기록
│   ├─ S5 가족 연결 관리 (코드 다시 받기, 연결 끊기) ← 홈 [가족] 칸
│   ├─ S6 광고 알림 끄는 법 (FR-040)
│   └─ S7 설정 (글자 크기 미리보기, 강력 모드, 데이터 지우기) ← 홈 [설정] 칸
│
└─ 보호자 모드
    ├─ O-G1 Google 로그인
    ├─ O-G2 QR 스캔 / 6자리 입력
    ├─ O-G3 연결 요청 대기 ("연결 요청을 보냈어요")
    ├─ O-G4 표시 이름 고르기 (연결 직후 한 번, 건너뛸 수 있음)
    ├─ G1 홈 (지켜보는 폰 상태 + 답변할 요청 + 지난 요청·폰 추가 연결, 연결 끊김 F6)
    ├─ G2 요청 상세 · 응답 (US4)
    ├─ G3 지난 요청 (날짜별, 결과 배지 하나. 알림 전용 요청은 '허용한 앱의 광고')
    └─ G4 설정 (연결된 폰 > 표시 이름·연결 끊기, 알림, 계정)
```

- 하단 탭 없음. 시니어 홈은 **스크롤 없는 한 화면**, 보호자 홈은 목록
- **보호자 화면의 상대 폰 이름** (2026-11-25): 부모님·엄마·시니어 같은 역할을 문구에 박지 않는다(사용자마다 관계가 다름). 이름은 아래 순서로 정한다.
  1. 보호자가 O-G4·G4에서 고른 표시 이름(엄마, 아빠, 할머니, 할아버지, 직접 입력). 보호자 폰에만 저장하고 서버로 보내지 않는다
  2. 상대가 S7에서 정한 이름 → "{이름}님 폰"
  3. "연결한 폰"
  - 폰은 "{표시 이름} 폰", 사람은 표시 이름 그대로. 연결 전 화면은 "상대 폰"·"지켜볼 폰"
  - 근거: Life360은 구성원이 정한 이름("Dad"도 사용자가 붙인 이름), Family Link는 사람별 요청·설정, 삼성 SmartThings Find는 "구성원" 같은 중립어 (§8 R13)
  - 예외(2026-11-25): 시스템 글꼴을 크게 해서 한 화면에 들어가지 않으면 위쪽(읽는 영역)만 스크롤하고, 줄 버튼(채운·테두리 버튼)은 아래에 고정한다
  - 홈의 누르는 영역(메뉴 칸, 그 위의 [켜러 가기])은 고정하지 않는다(2026-11-25): 자리가 남으면 바닥에 붙고, 넘치면 읽는 영역 아래에 이어 붙어 같이 스크롤한다. 고정하면 글꼴 200%에서 2×2 칸이 화면 대부분을 차지해 S1′ 앱 카드를 가렸다(S10+ 실측). 보통 크기에서는 보이는 모습이 같다. 근거: 메뉴가 많은 홈은 전체를 스크롤하고 바닥 고정은 주요 버튼 1~2개에만 쓰는 일반 관행, WCAG 1.4.4·1.4.10(키운 글자로 내용이 가려지면 안 됨) (§8 R9)

## 3. 핵심 흐름

### F1′. 앱 밖 광고 감지 → 승인 → 삭제 (주 흐름, 시연 시나리오 — US11)

```mermaid
sequenceDiagram
    autonumber
    actor 시니어
    participant SP as 시니어 폰<br/>(폰주치의)
    participant API as 서버
    participant GP as 보호자 폰<br/>(폰주치의)
    actor 보호자

    Note over 시니어,SP: 시니어가 조작하지 않는데<br/>설치된 앱이 전면 광고를 띄움
    Note over SP: 주기 작업(최소 15분, 실측 p95 ≤ 30분) / 앱 실행 시<br/>queryEvents로 조작 없는 전환을 앱에 귀속
    SP->>SP: symptom_event 기록 · 오늘 N번 → 기준 초과
    Note over SP: 허용 목록 앱인데 이 조합에 notice를 보낸 적 있고(alert_local)<br/>그 요청이 이미 닫혔으면 여기서 끝 — POST 안 함 (FR-007 조합당 1번)
    SP-->>시니어: 알림 "확인이 필요한 앱이 있어요" (허용 목록 앱이거나 같은 앱 요청이 열려 있으면 생략)
    SP->>API: POST /alerts (source: symptom, 허용 목록 앱이면 kind: notice)
    alt 같은 앱의 열린 요청 없음 · 허용 목록 아님
        API-->>GP: FCM ALERT_CREATED (high)
        GP-->>보호자: 알림 "{폰} 확인 필요 / ○○, 오늘 광고 N회"
    else 같은 앱의 열린 요청 없음 · 허용 목록 앱 ((pkg, cert, version) 조합당 1번)
        API-->>GP: FCM ALERT_NOTICE (normal)
        GP-->>보호자: 알림 "{폰} 허용한 앱 광고 / ○○, 오늘 광고 N회"
    else 같은 앱의 열린 요청 있음
        API-->>GP: FCM ALERT_UPDATED (근거 추가·최신 값으로 갱신, source·kind는 기존 값, 알림 없음)
    end
    Note over SP: 같은 날 6시간 상태 보고 때 횟수가 늘었으면 다시 POST<br/>→ 열린 요청 근거만 갱신 (재알림은 F3 일정대로)
    Note over 보호자,GP: 이후 F1의 8번(알림 탭 → G2)부터 같음
```

- 오버레이형 광고는 사용 기록에 안 남아 이 흐름으로 못 잡음 → 설치 시점 F1의 `OVERLAY_PERMISSION` 사전 경고가 보조 (ADR-0003 한계)

### F1. 설치 → 판정 → 승인 → 삭제 (설치 시점 사전 경고, 보조 — US1)

```mermaid
sequenceDiagram
    autonumber
    actor 시니어
    participant SP as 시니어 폰<br/>(폰주치의)
    participant API as 서버
    participant GP as 보호자 폰<br/>(폰주치의)
    actor 보호자

    시니어->>SP: 광고 속 [설치] → 광고 앱 설치됨
    Note over SP: WorkManager 주기 작업 / 앱 실행 시<br/>getChangedPackages로 감지 (최소 15분, 실측 p95 ≤ 30분)
    SP->>SP: 특징 추출 + 온디바이스 판정 (≤200ms)
    SP->>SP: verdict 저장 · RISK
    SP-->>시니어: 알림 "확인이 필요한 앱이 있어요"
    SP->>API: POST /alerts
    API-->>GP: FCM ALERT_CREATED (high)
    GP-->>보호자: 알림 "엄마 폰에 광고 앱이 설치됐어요"
    보호자->>GP: 알림 탭 → G2 요청 상세
    보호자->>GP: [지우자고 하기] (+ 한마디)
    GP->>API: POST /alerts/{id}/decision
    API-->>SP: FCM DECISION_MADE (high)
    SP-->>시니어: 알림 "딸이 이 앱을 지우자고 했어요"
    시니어->>SP: 알림 탭 → S2 → [이 앱 지우기]
    SP->>시니어: 시스템 삭제 확인창 (PackageInstaller.uninstall)
    시니어->>SP: [확인]
    SP-->>시니어: "지웠어요" 화면
    SP->>API: POST /alerts/{id}/outcome uninstalled
    API-->>GP: FCM ALERT_RESOLVED
    GP-->>보호자: "엄마가 앱을 지웠어요"
```

- ⚠️ 백그라운드에서 삭제 창을 바로 띄우는 건 **Android 백그라운드 액티비티 실행 제한**으로 불가 → 반드시 **시니어가 알림을 탭**해서 앱이 앞으로 나온 뒤 띄움
- 보호자가 [괜찮은 앱이에요]를 누르면 13~19 대신: 시니어 폰 허용 목록 추가, 시니어 알림 없음(이미 뜬 알림은 "가족이 괜찮다고 했어요"로 교체)

### F2. 가족 연결

```mermaid
sequenceDiagram
    autonumber
    actor 대행자 as 설치 대행자
    participant SP as 시니어 폰
    participant API as 서버
    participant GP as 보호자 폰

    대행자->>SP: O-S4 / S5 [가족 연결하기]
    SP->>API: POST /pairing-codes
    API-->>SP: 코드 482913 + QR (10분)
    대행자->>GP: O-G2 QR 스캔
    GP->>API: POST /pairing-codes/482913/accept
    API-->>SP: FCM LINK_REQUESTED
    SP-->>대행자: S3 "민지님과 연결할까요?" [연결할게요]
    대행자->>SP: (시니어 본인이 누르도록 안내) [연결할게요]
    SP->>API: POST /links/{id}/confirm
    API-->>GP: FCM LINK_ACTIVATED
```

- 시니어 확인 단계는 정책 근거(시니어 본인 동의)이자 오연결 방지. 생략 불가

### F3. 보호자 무응답

```mermaid
flowchart LR
    A[승인 요청 생성] --> B{24시간 내 응답?}
    B -- 예 --> Z[F1 계속]
    B -- 아니오 --> C[보호자 재알림 1회]
    C --> D{48시간 내 응답?}
    D -- 예 --> Z
    D -- 아니오 --> E[시니어 S2에 '가족에게 전화해 보세요' + 전화 버튼]

```

- 알림 전용 요청(`kind: notice`)은 재알림·시니어 안내 없이 7일 뒤 expired

### F4. 연결 끊기 (시니어)

홈 [가족] → S5 가족 연결 → 이름 옆 [연결 끊기] → 확인창 "민지님과 연결을 끊을까요? 민지님은 더 이상 알림을 받지 않아요" [연결 끊기]/[그대로 두기] → `DELETE /links/{id}` → 완료 문구

### F5. 강력 모드 (P3, 시연 기기 전용)

공장 초기화 → 설정 마법사에서 화면 6번 탭 → QR 스캔(프로비저닝 페이로드) → 폰주치의가 Device Owner로 설치 → 이후 F1의 15번 단계에서 **승인 즉시 앱 정지**, 시니어 S2에는 "가족이 이 앱을 잠시 멈췄어요" + [이 앱 지우기]

### F6. 연락 끊김 (보호자에게 알림)

시니어 폰이 폰주치의를 지웠거나, 알림을 껐거나, 꺼져 있으면 보호자는 "아무 일 없음"과 "보호가 멈춤"을 구분할 수 없다. 오탐을 줄이려고 조용히 두는 설계라 더 필요하다.

```mermaid
flowchart LR
    A[서버 lastCheckedAt] --> B{48시간 넘게 검사 완료 보고 없음?}
    B -- 아니오 --> Z[G1 카드: 마지막 검사 시각만]
    B -- 예 --> C[G1 카드 주황 경고 + 보호자 알림 1회]
    C --> D[📞 엄마께 전화하기 / 폰주치의가 켜져 있는지 확인하는 법]
```

- 기준 48시간: WorkManager 최소 주기(15분)·Doze 지연과 6시간 간격 상태 보고를 넉넉히 넘는 값. 실측 후 조정
- 요청이 없다는 것만으로 "지워졌다/꺼졌다"를 확정하지 않음 → 문구는 가능성 표현 유지. 권한이 꺼진 경우는 상태 보고(`protection`)로 따로 보여 줌: "{폰} 앱 밖 광고 찾기 꺼짐"
- 근거: 부모 통제 앱 사례의 "Monitoring gaps" 카드 [R2]
- 서버 쪽 판정 → 예약 작업(15분 간격)이 시니어 기기의 `lastCheckedAt`(openapi `Link.lastCheckedAt`으로 보이는 값, 보고가 없으면 연결 확정 시각) 기준으로 판정해 보호자에게 `CONTACT_LOST` 1번 (push-messages.md). 시니어 기기는 `PUT /devices/{id}/status`로 마지막 검사 시각·권한 상태를 6시간 간격 보고 (T055a). 다른 요청만 오는 기기(`lastSeenAt`만 갱신)는 정상으로 보지 않음

- 톤: 문장은 전부 해요체.
  - 시니어 화면: 버튼은 짧은 동사형([나중에], [지우기], [새 코드 받기], [연결할게요]), 상태는 문장("지금은 확인할 앱이 없어요")
  - 보호자 화면(2026-11-25): 공공·기업 앱처럼 필요한 것만. 상태·배지·버튼은 짧은 명사(확인 필요 1건, 연결 끊김, 답변 대기, [허용], [삭제 요청], [저장], [닫기]). KRDS 버튼 가이드는 동사형을 원칙으로 하되 완료·취소·삭제처럼 흔한 작업은 명사를 허용한다. 안내 문장은 해요체 한 줄, 한 문장 레이블에는 마침표를 찍지 않는다(Material). 사람이 주어인 문장 대신 사실을 쓴다("사용 중이 아닐 때 광고 오늘 12회") (§8 R10~R12, R14)
- 용어: 연결용 6자리는 "코드"로 통일(화면, 버튼, 코드 만료 문구, 보호자 화면 모두)
- 조사 처리: `{앱이름}을(를)` 대신 받침 판별 함수로 자동 선택. 보호자 문구는 조사가 붙지 않게 쓴다("{앱이름}, 오늘 광고 12회")

## 7. 접근성 점검표 (구현 시 체크)

- [ ] 시스템 글꼴 200% + 시니어 추가 배율 1.3에서 S1·S2·S3 잘림 없음 (Compose UI 테스트 `fontScale = 2f`). 홈 메뉴 칸이 늘어나고, 버튼 쌍은 넘치면 세로로 쌓이는지 확인. S1′ 앱 카드가 메뉴 칸에 가리지 않고 메뉴는 스크롤로 이어지는지 확인
- [ ] 모든 아이콘 버튼에 `contentDescription`, 상태 원은 `stateDescription`
- [ ] TalkBack 순서: 상태 문장 → 주요 버튼 → 나머지
- [ ] 색만으로 상태 구분 안 함 (아이콘 ✓ / ! + 문장)
- [ ] 화면 전환·자동 닫힘 타이머 없음
- [ ] 스와이프 전용 조작 없음 (알림 넘기기 등은 버튼으로도 가능)
- [ ] 본문 대비 7:1, 큰 글씨 4.5:1 이상 (보호자 배지 포함, §5 배지 토큰)
- [ ] 보호자 화면 문구에 부모님·엄마·시니어가 고정 문자열로 없음 (표시 이름 변수만, §2)
- [ ] 터치 영역 시니어 56dp / 보호자 48dp 이상 (`Modifier.minimumInteractiveComponentSize`)
- 기준: WCAG 2.2 AA(+본문 AAA 대비), 서울시 고령층 친화 디지털 접근성 표준 10대 지침, Material 3 접근성
